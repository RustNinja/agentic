## Highest Priority Gaps

These should become focused fixtures first. The generic slicer fix must target
the shape of each Rust construct, not a Litter-specific path or symbol name.

### 1. Async actor loops and command channels

Evidence:

- `codex-ipc/src/client/connection.rs` uses `tokio::spawn`, `mpsc`,
  `broadcast`, read/write loops, `JoinHandle` fields, and shutdown methods.
- `codex-ipc/src/client/reconnect.rs` uses `tokio::select!`, `watch`,
  `broadcast`, `mpsc::UnboundedReceiver`, nested reconnect loops, and boxed
  async connector callbacks.
- `codex-mobile-client/src/session/connection.rs` has command enums, command
  channels, worker `tokio::select!` loops, and nested `tokio::spawn` calls.

Fixture ideas:

- `async.actor_loop.channel_command.001`: selected API sends one command enum
  variant over `mpsc`; the retained worker loop keeps only the live variant
  handler while preserving channel types, sender/receiver wiring, and task
  handles.
- `async.select_reconnect_loop.001`: selected API retains a reconnect loop with
  `watch`, `broadcast`, and invalidation branches while dead branch helpers are
  pruned.
- `async.join_handle_shutdown_surface.001`: selected shutdown API keeps the
  task handle fields and abort paths without keeping unrelated worker commands.

### 2. FFI export surfaces

Evidence:

- `codex-bridge/src/lib.rs` has `#[unsafe(no_mangle)] pub extern "C"` exports,
  target-gated iOS/android modules, and platform initialization.
- `codex-bridge/src/android_jni.rs` and
  `codex-mobile-client/src/android_context.rs` have `extern "system"` JNI
  entrypoints with `JNIEnv`, `JClass`, `JString`, and `jint`.
- `codex-bridge/src/ios_exec.rs` imports unsafe extern functions behind iOS
  cfg gates.

Fixture ideas:

- `ffi.no_mangle_export_surface.001`: selected C ABI export keeps pointed-to
  helper functions, pointer/string conversion helpers, and free functions.
- `ffi.jni_extern_system_entrypoint.001`: selected JNI export keeps JNI import
  paths and argument types while pruning unused sibling JNI exports.
- `ffi.unsafe_extern_import_cfg_module.001`: selected platform export keeps the
  cfg-gated unsafe extern import module as an intact platform surface.

### 3. Clap derive command contracts

Evidence:

- `codex-debug-cli/src/main.rs` uses `#[derive(clap::Parser)]`,
  `#[derive(clap::Subcommand)]`, `#[derive(clap::Args)]`,
  `#[command(subcommand)]`, `#[arg(long, default_value = ...)]`,
  `value_delimiter`, and `conflicts_with`.

Fixture idea:

- `macro.clap_nested_command_contract.001`: selected parser root keeps nested
  command and args enums/structs referenced only through clap derives and
  helper attributes; dead subcommands are pruned when not part of the selected
  parser surface.

### 4. Thiserror derive field contracts

Evidence:

- `codex-ipc/src/error.rs` uses `#[derive(thiserror::Error)]`, `#[from]`
  fields, tuple variants, struct variants, and format captures.
- `codex-ipc/src/conversation_state.rs` uses source-carrying error variants
  and formatted field references.
- `codex-mobile-client` combines `thiserror::Error` with `uniffi::Error` in
  FFI-facing errors.

Fixture ideas:

- `macro.thiserror_from_source_contract.001`: retained public error type keeps
  source/from field dependencies and the conversion impl closure generated by
  the derive.
- `macro.thiserror_format_capture_fields.001`: retained error type keeps fields
  referenced only by format captures inside `#[error(...)]`.

### 5. Async I/O trait impls and poll methods

Evidence:

- `codex-mobile-client/src/alleycat.rs` implements `AsyncRead` and
  `AsyncWrite` for a stream wrapper with `poll_read`, `poll_write`,
  `poll_flush`, `poll_shutdown`, `Pin<&mut Self>`, `Context`, `Poll`, and
  `ReadBuf`.
- `codex-ipc/src/transport/frame.rs` uses generic helpers over
  `R: AsyncRead + Unpin` and `W: AsyncWrite + Unpin`.

Fixture ideas:

- `trait.async_io_poll_impl.001`: selected constructor or connector keeps the
  stream wrapper and both external trait impls, including associated poll
  method imports.
- `trait.async_io_generic_frame_helpers.001`: selected frame helper keeps
  extension trait imports and generic async read/write bounds without pulling
  unrelated transport helpers.

### 6. Stateful globals and runtime singletons

Evidence:

- `codex-ipc/src/wire_trace.rs` uses `OnceLock<Arc<dyn Fn...>>`.
- `codex-mobile-client/src/ffi/shared.rs` uses `OnceLock` for a shared Tokio
  runtime, mobile client, and platform init.
- `codex-mobile-client/src/android_context.rs` stores `GlobalRef` in
  `OnceLock`.
- `codex-mobile-client/src/plugin_refs.rs` uses `LazyLock<Regex>`.
- Several app/store modules use global mutex-backed registries.

Fixture ideas:

- `static.once_lock_global_runtime_surface.001`: selected public facade keeps
  `OnceLock::get_or_init` initializers, runtime builder imports, and platform
  init helpers.
- `static.lazy_regex_constructor.001`: selected parser keeps `LazyLock<Regex>`
  and constructor closures without keeping unrelated parser functions.
- `static.global_mutex_registry.001`: selected registry operation keeps the
  global mutex and lock/error paths but prunes unrelated registries.

### 7. Platform cfg plus assets plus externs

Evidence:

- `codex-mobile-client/src/session/connection.rs` has iOS cacert
  `include_bytes!` under cfg and platform runtime setup.
- `codex-bridge/src/lib.rs` combines target cfg modules, `include_bytes!`,
  `std::env` mutation, and exported FFI initialization.
- `codex-bridge/Cargo.toml` and `codex-mobile-client/Cargo.toml` combine
  `cdylib`/`staticlib` crate types with target-specific dependencies.

Fixture ideas:

- `cfg.platform_asset_extern_bundle.001`: selected platform init keeps target
  cfg modules intact, copies cfg-gated assets, and retains only the platform
  externs/helpers needed by the selected root.
- `manifest.cdylib_staticlib_target_patch_bundle.001`: selected FFI crate keeps
  crate type, target deps, features, workspace patches, and lock/toolchain
  context without keeping unrelated packages.

### 8. Serde protocol projection and custom helpers

Evidence:

- `codex-mobile-client/src/hydration.rs` uses adjacent tagging with
  `#[serde(tag = "type", content = "value", rename_all = "camelCase")]`.
- `codex-mobile-client/src/parser.rs` has custom string/numeric duration
  serialize/deserialize helpers.
- `codex-mobile-client/src/pets.rs` and `alleycat.rs` use field aliases.
- `codex-ipc/src/conversation_state.rs` projects external protocol enum
  variants through state mutation helpers.

Fixture ideas:

- `serde.adjacent_tag_content_contract.001`: retained DTO enum keeps payload
  variants and nested payload records used only by serde tag/content metadata.
- `serde.custom_numeric_string_helpers.001`: retained DTO keeps custom
  serializer/deserializer helper functions referenced only through serde attrs.
- `pattern.external_protocol_variant_projection.001`: retained state reducer
  keeps external enum variants, conversion helpers, and JSON mutation helpers
  used by reachable match arms while pruning unrelated protocol variants.

- `serde.custom_numeric_string_helpers.001`

Two generic fixes came from those fixtures:

- Private enum variants are now pruned when only dead code mentions them, while
  public/root/derive/serde/clap/thiserror/UniFFI enum contracts keep full
  variant surfaces.
- Target-cfg `extern` blocks are kept intact, because host validation cannot
  prove target-specific foreign imports unused.
